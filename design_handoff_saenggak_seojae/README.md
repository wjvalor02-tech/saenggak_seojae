# Handoff: 생각서재 — AI가 저절로 정리해 주는 개인 생각 기록 앱

## 개요
사용자는 주제·폴더·태그를 고르지 않고 **쓰기만** 한다. 저장하면 AI가 분야(카테고리) › 갈래(하위분류), 태그, 한 줄 요약을 붙이고, 글이 쌓일수록 분류 체계가 자라며 관련 글끼리 연결된다.

- 사용자: 역사 교사이자 교육방법 전공 교육대학원생 (본인 1인 사용). 수업 아이디어·연구 메모·독서·육아·일상·운동 기록이 섞여 들어옴.
- 최우선 원칙: **입력까지의 마찰 최소화.** 앱을 열면 바로 커서가 있는 큰 입력창.
- 톤: 노트앱이 아니라 차분한 개인 서재. 넉넉한 여백, 읽기 편한 명조 본문.
- 모바일 우선, 데스크톱에서도 자연스럽게. 한국어 UI.

## 디자인 파일에 대해
`prototype/` 안의 파일은 **HTML로 만든 디자인 레퍼런스**다. 그대로 배포할 코드가 아니라, 의도한 모양과 동작을 보여주는 프로토타입이다. 할 일은 이 디자인을 실제 앱 환경에서 **다시 구현**하는 것이다. 기존 코드베이스가 없으므로 아래 "권장 구현 방향"을 참고해 적절한 스택을 고른다.

- `app.dc.html` — **기준 프로토타입(실사용판)**. 빈 상태로 시작하며 모든 기능이 들어 있다. 로직 전체가 파일 하단 `<script data-dc-script>`의 `class Component` 안에 있다(상태·분류 휴리스틱·AI 프롬프트·네트워크 레이아웃 등). 구현 시 이 코드를 동작 명세로 읽을 것.
- `demo-with-sample-data.dc.html` — 예시 글 17편이 든 이전 버전(일부 최신 기능 없음). 화면이 채워졌을 때의 모습 참고용.
- `design-options.dc.html` — 초기 비교 시안 캔버스. 채택안: 빠른 기록 = **1j(몰입 모드 + 바텀시트)**, 서재 = **1m(책장)**.
- `support.js` — 프로토타입 런타임. 구현과 무관.
- 프로토타입은 브라우저에서 바로 열린다. AI 기능(`window.claude.complete`)은 디자인 도구 안에서만 작동하고, 밖에서는 키워드 휴리스틱으로 대체된다.

## 충실도
**하이파이.** 색·타이포·간격·문구·인터랙션이 확정안이다. 픽셀 단위로 재현하되 컴포넌트 구조는 선택한 프레임워크의 관례를 따른다.

## 권장 구현 방향 (제안)
사용자는 이 앱을 **모바일과 데스크톱에서 계속 실사용**하길 원한다. 프로토타입에서 겪은 문제는 **기록 유실**이었다(브라우저 저장소가 접속마다 초기화됨). 따라서 **서버 저장과 동기화가 1순위 요구사항**이다.

- **앱 형태:** PWA(설치형 웹앱). 하나의 코드로 iOS·Android·데스크톱을 커버하고 홈 화면에 설치할 수 있다. 예: Vite + React + TypeScript, 또는 Next.js.
- **저장/동기화:** Supabase(Postgres + Auth) 또는 유사 서비스. 1인용이므로 매직링크나 OAuth 로그인 하나면 충분하다. 오프라인일 때는 IndexedDB에 큐로 쌓았다가 온라인이 되면 동기화한다(입력 마찰 최소화 원칙상 오프라인 쓰기는 필수).
- **AI:** 서버 측 함수(Edge Function 등)에서 호출한다. API 키는 절대 클라이언트에 두지 않는다. **1차 제공자는 Google Gemini(무료 한도로 시작), 나중에 Claude로 교체 가능**하게 만든다 — 아래 "AI 제공자 구조" 참고. 프롬프트와 JSON 스키마는 "AI 기능 명세"를 그대로 쓴다.
- **음성 입력:** 1차는 Web Speech API(`webkitSpeechRecognition`, `ko-KR`). Android Chrome과 iOS Safari 14.5+에서 동작한다. 지원하지 않는 환경이나 장문 녹음은 2차로 MediaRecorder 녹음 → 서버 STT로 처리한다.
- **백업:** JSON 내보내기·가져오기는 유지한다. 스키마는 아래 "데이터 모델".

  - 연결 이유 배지: "같은 태그 #학습부진" 또는 "같은 갈래 · 역사교육"

    - 작은 점 = 태그. 지름 `8 + 8×비율`px, `#2F5A4B`, 아래 라벨 12.5px
    - 태그는 2회 이상 나온 것 우선, 최대 10개
    - 선 = 분야와 태그가 함께 나온 관계. 굵기 `1 + 2×(공동출현/최대)`, 색 `#CFC7B8`
  - **레이아웃 알고리즘:** 단순 힘 기반 배치를 320회 반복하고, 결과는 데이터가 바뀔 때만 다시 계산(메모이즈)한다. 세부는 `layoutNet()` 참고. d3-force 등으로 대체해도 된다.
  - 원이나 점을 누르면 연결된 노드만 남기고 나머지는 투명도 0.28~0.35로 흐린다. 활성 선은 `#2F5A4B`. 아래에 "#태그 · 이번 달 N편"과 글 목록이 나온다. 다시 누르거나 "닫기"를 누르면 해제된다.
  - 통계: "이번 달 기록 N편", "새로 자란 갈래 …"
- 날짜순 흐름
  - 좌측 64px 날짜 열: "11.10" 명조 18px/700 + 요일 12px
  - 우측: 세로선 + 글 목록(분야 경로 + 요약 17px)

### 6. 검색 (`search`)
- 입력창: 아래 테두리 1.5px `#2B2722`, 18px. 플레이스홀더 "키워드, 또는 “그때 ~에 대해 뭐라고 썼더라?”"
- **자연어 판별:** 입력에 `더라|했었|썼지|언제|뭐라|어떻게|?|있었`이 있으면 자연어 질문으로 보고 "물어보기" 버튼(`#2F5A4B`)을 띄운다. Enter도 같은 동작.
- 빈 입력일 때는 예시 질문 3개를 보여준다(누르면 바로 실행).
- AI 답변 카드: "기록에서 찾은 답" + 명조 18px 답변 + 근거 글 링크(최대 3개, "11.10 요약 →")
- 키워드 결과: "‘X’ 포함 N편" + 목록(날짜 · 분야 경로, 요약, 본문 2줄). `#태그` 형식도 검색된다.

### 4-a. 도서 자동 인식 (빠른 기록 중)
- 마지막 입력 후 1.2초 디바운스
- 트리거
  - 제목이 『』《》「」<> 중 하나로 감싸져 있으면 그 제목으로 바로 찾는다.
  - 괄호가 없으면 글에 `책|읽|저자|작가|소설|에세이|완독|밑줄`이 있을 때 AI가 글에서 책을 추출한다.
- 카드: 배경 `#FBF9F5`, 테두리, radius 12. 34×46 책 모양(`oklch(0.42 0.06 25)`) + 『제목』 16.5px/700 + 메타 13.5px + 안내 12px "AI가 찾은 정보예요. 다르면 지워주세요." + "×"(44px)
- 저장할 때 `note.book`으로 붙는다. 분류 프롬프트에 "[이 글은 책 『…』에 관한 기록]"을 앞에 붙여 보낸다.
- 실제 앱에서는 **국립중앙도서관 / 알라딘 / 카카오 책검색 API 등 실제 서지 DB로 검증**하길 권장한다. 프로토타입은 AI 지식에만 의존한다.

### 4-b. AI 팩트체크 (저장 전, 선택 사항)
- "AI 검토" 버튼을 눌렀을 때만 실행한다(저장을 막지 않음).
- 상태별 표시
  - 검토 중: "사실관계를 확인할 부분을 찾는 중…"
  - 없음: 초록 배너 "따로 확인할 내용이 없어요."
  - 결과: "확인해 볼 내용 N" 카드 + 안내 "AI가 아는 범위의 검토예요. 고치지 않고 저장하면 이 목록이 글에 함께 남아요."
- 항목 구성
  - 등급 배지(한 줄, `white-space: nowrap`): "오류 가능"(`#9A4A3A` / `#F3E3DE`) 또는 "확인 권장"(`#7A5A1E` / `#F3EAD3`)
  - 인용 하이라이트(명조 15px, 배경 `#F3EAD3`)
  - 확인할 점 14.5px
  - 메모 13.5px `#5F584F`
  - "×"
- 남은 항목은 `note.checks`로 저장한다. 실제 앱에서는 웹 검색 기반 검증을 붙일 수 있다.

### 음성 기록 (모바일)
- 마이크 버튼은 900px 미만에서만 보인다(`voiceOnDesktop` 옵션으로 데스크톱에서도 켤 수 있음).
- 인식 설정: `lang='ko-KR'`, `continuous`, `interimResults`. 중간 결과를 실시간으로 본문에 이어 붙인다. 기존 글이 있으면 공백 하나를 넣고 이어 쓴다.
- 다시 누르거나 저장하면 녹음이 멈춘다.
- 오류 문구
  - 권한 거부: "마이크 권한이 필요해요…"
  - 미지원 브라우저: "키보드의 마이크 버튼을 써 주세요"
  - no-speech: 조용히 무시한다.
- 음성으로 들어온 글도 일반 글과 똑같이 분류된다. 향후 "말로 쓴 글" 표시나 문장부호 다듬기(AI) 후보.

## AI 제공자 구조 (필수)
비용을 최소화하려고 **Gemini 무료 한도로 시작**하고, 분류 품질이 아쉬우면 **Claude로 바꾼다.** 교체가 설정 한 줄로 끝나도록 AI 호출을 한 곳에 모은다.

- **단일 진입점:** 서버에 `ai/complete(prompt, { json: true, timeoutMs })` 하나만 두고, 앱의 모든 AI 기능(분류·도서·팩트체크·자연어 검색)은 이것만 호출한다. 화면 코드에서 특정 회사 SDK를 직접 부르지 않는다.
- **어댑터:** `providers/gemini.ts`, `providers/anthropic.ts`. 둘 다 `(prompt, opts) => Promise<string>`를 구현한다.
- **선택은 환경변수로:** `AI_PROVIDER=gemini|anthropic`, `AI_MODEL=<모델명>`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`. 기본값은 `gemini`. 모델명은 코드에 하드코딩하지 말고, 구현 시점의 각 사 문서에서 최신 경량 모델을 확인해 기본값으로 넣는다(Gemini는 Flash 계열, Claude는 Haiku/Sonnet 계열).
- **JSON 응답:** Gemini는 `responseMimeType: "application/json"`(가능하면 `responseSchema`도), Claude는 "JSON만 출력" 지시를 쓴다. 공통 후처리로 응답에서 `{…}`를 추출해 파싱하고, 스키마 검증(zod 등)에 실패하면 1회 재시도한 뒤 휴리스틱으로 대체한다.
- **한도·오류 처리:** 무료 한도 초과(429)나 장애가 나면 → 저장은 그대로 진행하고 휴리스틱으로 분류한 뒤 `note.aiPending = true`로 표시한다. 나중에 백그라운드에서 다시 분류한다. 사용자에게는 저장 시트에 "AI 연결이 잠시 어려워 간단히 분류했어요. 곧 다시 정리할게요." 정도만 알린다. **AI가 실패해도 기록은 절대 막히지 않아야 한다.**
- **비용 보호:** 하루 호출 수 상한(`AI_DAILY_LIMIT`)과 간단한 사용량 로그를 둔다. 자연어 검색은 기록 전체를 보내지 말고 키워드/임베딩으로 후보 30~50개를 추린 뒤 보낸다(무료 한도와 토큰 절약).
- **개인정보 참고:** Gemini 무료 등급은 입력 데이터가 서비스 개선에 쓰일 수 있다(약관 확인 필요). 육아·개인 기록이 섞이므로, 민감하면 유료 등급이나 Claude로 전환하라고 설정 화면에 한 줄 안내한다.
- **설정 화면(선택):** "AI 제공자: Gemini / Claude", 이번 달 호출 수 표시.

## AI 기능 명세 (서버 함수로 옮길 것)
네 가지 모두 위의 `ai/complete` 하나를 거쳐 호출하고 **JSON만 반환**하게 한다. 프롬프트는 회사와 무관하게 공통으로 쓴다. 실패하거나 시간이 초과되면(15~20초) 조용히 휴리스틱으로 대체하거나 기능을 생략한다.

1. **분류** `classify(text, taxonomy)` → `{"cat","sub","tags":[],"summary"}`
   - cat은 기존 분야 key 중 하나여야 한다.
   - sub는 기존 갈래를 우선 쓰고, 맞는 게 없으면 새 이름(2~6자)을 만든다.
   - 성격이 다른 내용이 섞이면 둘을 아우르는 갈래를 고른다(예: 근력+유산소).
   - 태그는 2~3개, 띄어쓰기 없는 명사.
   - 요약은 30자 이내, 명사형으로 끝낸다.
   - 프롬프트에 사용자 프로필(역사 교사 / 교육방법 대학원생)과 현재 분류 체계 전체를 넣는다.
2. **도서 인식** → `{"book":{"title","author","translator","publisher","year","originalYear"}}` 또는 `{"book":null}`
   - 한국어판이 있으면 한국어판 기준으로 답한다.
   - 실재하는 책인지 확신이 없으면 null.
3. **팩트체크** → `{"checks":[{"quote","level":"오류 가능|확인 권장","issue","note"}]}`
   - 최대 5개.
   - 개인 경험·감정·의견·계획은 검토 대상이 아니다.
   - "오류 가능"은 틀렸다고 확신할 때만 쓴다.
4. **자연어 검색** → `{"answer","ids":[]}`
   - 기록 전체를 넘긴다(id | 날짜 | 분야›갈래 | 요약 | 본문 앞 180자).
   - 답은 2~3문장 존댓말로, "11월 10일"처럼 날짜를 언급한다.
   - 근거 id는 최대 3개.
   - 기록이 많아지면 임베딩 검색으로 후보를 먼저 줄인 뒤 넘긴다(pgvector 등).

정확한 프롬프트 원문은 `app.dc.html`에서 `const prompt =`로 검색하면 나온다.

**휴리스틱 대체(오프라인/AI 실패 시):** `heuristic()`이 정규식으로 분야·갈래를 판별하고(운동: 유산소/근력/근력+유산소 구분 포함), `TAG_RULES`로 태그를 붙이고, 첫 문장으로 요약을 만든다. 오프라인으로 저장한 글은 나중에 온라인이 되면 AI로 다시 분류하는 것을 권장한다.

## 시작하기 (사용자 준비물)
1. Google AI Studio에서 Gemini API 키 발급 → `GEMINI_API_KEY`
2. (나중에 교체할 때) Anthropic Console에서 API 키 발급 → `ANTHROPIC_API_KEY`, `AI_PROVIDER=anthropic`

## 데이터 모델
```ts
type Category = { key: 'research'|'class'|'reading'|'parent'|'daily'|'exercise';
  name: string; emoji: string; hue: number; subs: { name: string; born: 'YYYY-MM-DD' }[] };
type Note = { id: string; date: 'YYYY-MM-DD'; cat: Category['key']; sub: string;
  tags: string[]; summary: string; body: string;
  book?: { title: string; author?: string; translator?: string; publisher?: string; year?: string; originalYear?: string };
  checks?: { quote: string; level: '오류 가능'|'확인 권장'; issue: string; note: string }[];
  edited?: 'YYYY-MM-DD';
  aiPending?: boolean;            // AI 실패로 휴리스틱 분류됨 → 나중에 재분류
  aiProvider?: 'gemini'|'anthropic' };  // 어떤 AI가 분류했는지
// 백업 JSON: { app:'생각서재', version:1, saved, cats: Category[], notes: Note[] }
```
- 초기 분야는 6개로 시작하고 갈래는 비워 둔다(**A안**: 분야는 고정, 갈래만 AI가 키움).

| key | 이름 | 이모지 | hue |
|---|---|---|---|
| research | 연구 | 📚 | 160 |
| class | 수업 | ✏️ | 60 |
| reading | 독서 | 📖 | 25 |
| parent | 육아 | 🌱 | 125 |
| daily | 일상 | ☕ | 290 |
| exercise | 운동 | 🏃 | 225 |

- 실제 DB에서는 `created_at`(시각까지), `updated_at`, `user_id`, `deleted_at`(동기화용 소프트 삭제)을 추가한다.
- 프로토타입이 만든 백업 JSON을 가져올 수 있게 하는 **가져오기 기능을 꼭 넣는다**(사용자가 테스트 기록을 옮길 수 있도록).
- 상대 날짜 규칙: 오늘 / 어제 / N일 전 / N주 전 / N달 전.
